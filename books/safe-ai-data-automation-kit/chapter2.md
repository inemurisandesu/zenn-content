# 第2章：文字コード混在・金額誤差・異常行に耐えるPythonデータ処理レシピ

実務のデータ自動化で最も時間と信頼を奪うのは、「テストデータでは通ったのに本番CSVで落ちる」トラブルです。本章では、実際に検証済みの `csv_sales_reporter` の設計をもとに、落ちないバッチ処理の標準型を整理します。

## 1. 入力レイヤ：エンコーディング自動判別とBOM対策

日本の業務データでは、同一システム由来であっても担当者がExcelで上書き保存した瞬間に `UTF-8` → `CP932 (Shift-JIS)` へ変わることがあります。

- `utf-8-sig` を最優先に試すことでBOM（`\ufeff`）によるヘッダー不一致を防ぐ
- 失敗時に `cp932` へフォールバックする
- デコード不能ファイルは明示的なエラーで失敗理由とファイル名を記録する

## 2. 値変換レイヤ：Decimal と全角/半角記号の正規化

金額や数量は `float` を使わず `Decimal` で統一します。

- `replace("¥", "").replace("￥", "").replace(",", "").replace("円", "")` のように半角・全角の双方を除去
- `value.is_finite()` を検証し、`NaN` や `Infinity` が集計に混入するのを防ぐ
- 負数や空欄など業務ルール外の値は例外でバッチ全体を止めず、`AnomalyRecord` に分離する

## 3. 監査可能な出力レイヤ

1回のバッチ実行で、以下の4ファイルをセット出力する設計が実務では最も運用しやすくなります。

| ファイル | 役割 | エンコーディング |
| --- | --- | --- |
| `category_summary.csv` | Excelでそのまま開ける集計結果 | `utf-8-sig` |
| `anomalies.csv` | 弾いた異常行の行番号・理由・生JSON | `utf-8-sig` |
| `summary.json` | 後続の自動処理・監視スクリプト用 | `utf-8` |
| `report.md` | 人間が数秒で確認できるサマリー | `utf-8` |

## 4. テスト設計の要点

テストデータ作成時に、あえて「CP932バイト列（全角 `￥` 含む）」「UTF-8 BOM」「重複ID」「不正日付」「負数金額」を1つのテストケースに同居させておくと、将来のリファクタリングで地雷を踏みにくくなります。
