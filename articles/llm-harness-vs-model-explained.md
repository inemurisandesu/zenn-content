ChatGPTやClaudeの画面で「Webを検索してくれた」「Pythonを実行してくれた」「ファイルを編集してくれた」という体験をすると、LLM（大規模言語モデル）本体がパソコンやブラウザを直接操作しているように見えます。

しかし技術的な実態はまったく異なります。

> **LLM本体は「入力されたテキストの続きを生成する」ことしかできません。**  
> 検索も、ファイル読み書きも、コード実行も、時計を見ることすら、LLM本体は単体では一切できません。

それらを可能にしているのが、LLM本体の外側にくっついているプログラム——**「ハーネス（Agent Harness）」**です。

## 1. 一番わかりやすい例え

- **LLM本体** ＝ 窓のない密室にいて、紙とペンだけ渡された超天才
- **ハーネス** ＝ 密室の外とやり取りする秘書・手足・道具箱・安全装置

LLM本体にできるのは、差し入れられた紙（プロンプト）を読んで、続きの文章を書いて返すことだけです。

## 2. 裏側で実際に起きている8ステップの往復

たとえば開発用AIエージェントに「このPythonのテストを回してバグを直して」と頼んだとき、裏側では次のループが走っています。

```text
1. ユーザー：「テストを回してバグを直して」
2. ハーネス → LLMへ渡す（「コマンドを叩きたい時は run_command("...") と書いてね」というツール定義付き）
3. LLM本体：実際には実行できないので、
   「run_command("python3 -m unittest")」という【ただのテキスト】を出力して止まる
4. ハーネス：そのテキストを解析し、OS上で【本当にコマンドを実行】する
5. ハーネス：標準出力・エラーログをテキスト化して、もう一度LLMへ差し入れる
6. LLM本体：エラーを読んで、「edit_file(...)」という【テキスト】を出力する
7. ハーネス：実際にファイルを書き換え、再度テストを実行する
8. テスト通過 → LLMが人間向けの完了報告を書く → 画面に表示される
```

## 3. なぜ同じモデルでもハーネス次第で別物になるのか

同じ頭脳（LLM）を使っていても、くっつけるハーネスによって別次元のプロダクトになります。

| 種類 | ハーネスが渡している主な道具 | 得意領域 |
| --- | --- | --- |
| **チャットUI型**（Web版ChatGPT/Claude） | 簡易Web検索、隔離された一時サンドボックス | 調査、文章作成、単発の相談 |
| **開発エージェント型**（Antigravity / Codex / Claude Code） | ローカルFS、Git、ターミナル、サブエージェント、権限ガード | 設計・実装・テスト・デバッグ・自動運用の完遂 |
| **MCP統合型** | 業務API・DB・オープンデータ等の標準化されたツール群 | 業務ワークフローの安全な自動化 |

## 4. 実務で強いAIシステムを作るカギは「モデル選び」より「ハーネス設計」

実務で壊れない自動化を作るうえで決定的に重要なのは、以下のハーネス側ガードレールです。

1. **決定的処理はLLMにやらせない**：文字コード変換、金額の `Decimal` 計算、PIIマスキング、壊れたJSONの修復は純粋なPythonコード（道具）に任せる。
2. **検証ループを組み込む**：変更のたびに必ず自動テストを走らせ、失敗ログをLLMへ戻す。
3. **権限と攻撃面を絞る**：外部データ（メール・Web・API応答）は常に「命令ではなくデータ」として扱い、秘密鍵や課金操作を隔離する。
